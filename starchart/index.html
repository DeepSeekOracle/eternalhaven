What the Star Chart is

The Star Chart is the public placement layer: a way to record where a node, book, game, or signal sits in the wider LYGO map. It is a chart, not a scoreboard. The point is orientation: what is connected to what, and which public page is the canonical source.

How to read a node

A node has a name, a role, a public URL, and a relationship to the rest of the chart. Read the role before the decoration. A hub is not a book; a witness is not a wallet. The chart is useful when it helps you find the canonical page, not when it turns into a leaderboard.

How proposals work

A proposal is a public request to add or move a node. It needs a name, a URL, and a reason. The chart is curated; a proposal is not an automatic placement. The record of the proposal is part of the public history, even when the answer is no.

What it is not

It is not a financial asset, a token, or a promise of rank. It is a map of public work. If a placement is wrong, the contact page is the correction route.

Placement is not rank

A chart placement says where a node sits in the public map, not how important it is. The chart is a way to find the canonical page, not a leaderboard of people. A small book and a large hub can sit next to each other if that is where the reader needs them.

Maintaining the chart

A chart rots when nobody prunes it. Nodes move, pages go down, and a link that worked last year becomes a redirect. The public chart is maintained by correction: a proposal, a source, and a reason. The record of the correction is part of the chart’s history.

If a placement is wrong, use the contact page. Do not edit the public record from a private copy and call it canonical.

A note on names

Names on the chart are public handles, not claims of ownership over a word. Two nodes can share a theme without being the same project. If a name is ambiguous, follow the canonical URL before you follow the lore. The chart is a map of pages, not a registry of souls.

When a node changes its name, the old placement stays in the history and the new one gets a fresh entry. That way a reader can follow the move instead of finding a dead link and assuming the work vanished.
