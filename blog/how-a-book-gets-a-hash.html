How a book gets a hash

An ISBN names a book. A hash proves it is still the book. One is paperwork; the other is a receipt, and a small catalog needs both.

JH
Justin Helmer
6 November 2026 · about a nine-minute read

When The Unwritten Seal went live as an ebook, I did two pieces of paperwork. The first was an ISBN, because a book needs a name a store can order. The second was a SHA-256, because a book needs a way to prove that the file you are holding is the file I wrote. The first one I filled in on a form. The second one I typed into a terminal at one in the morning, and it has done more for my peace of mind than the form did.

This essay is the plain-language version of that second piece of paperwork, written for writers rather than engineers. If you already know what a hash is, skip to the section about what it cannot do. That section is the only one I would defend in an argument.

What a hash actually is

A hash is a fingerprint computed from the bytes of a file. Feed the file into a function and you get back a fixed-length string of letters and numbers. Change one character in the file and the string changes completely. You cannot work backwards from the string to the file, and no one has ever found a practical way to make two different files with the same string on purpose.

That is it. That is the whole technology. It is not a blockchain, it is not a signature, and it does not prove authorship. A hash only proves one thing: the bytes you have now are the bytes that produced that number. If you also trust the source that published the number, you have something useful.

Why a small press should bother

Three reasons, in order of how much they matter.

First, edition control. Every store re-packages an ebook. Some add tracking pages, some re-flow the CSS, some strip the cover. If I publish one number and the store's edition does not match it, that is information, not a scandal. It tells me the file has been through a packaging step, and I can decide whether that step changed anything that matters.

Second, an end to a specific argument. Every writer eventually meets someone who claims a different edition is the original, or that a paragraph was removed, or that the book they have is the "real" one. With a published hash, that argument takes thirty seconds: compute, compare, done. Without it, the argument is about memory and vibes, and I lose either way.

Third, it changes my own habit. Writing down a number forces me to freeze a file. A lot of small-press chaos comes from never deciding when a book is finished, then editing it in four places forever. A hash is a small ceremony: this is the text. Future edits get a new number and a note in the changelog.

What a hash cannot do

It cannot prove I wrote the book. Anyone can hash a file. The hash is a receipt for a copy, not a birth certificate for an idea.

It cannot prove the text is unchanged across formats. An EPUB on one store and a PDF on another produce different bytes and different hashes for the same novel. If you want to compare the reading experience, you compare extracted text, not file bytes. The number protects the artifact, not the meaning.

It cannot survive a re-typeset with a new line break and still match. This is the part that annoys people. A perfectly innocent process — a retailer's re-flow, a corrected typo, a new font — changes the hash and looks, to a suspicious reader, exactly like tampering. So the number has to come with a sentence: this is the file I published on this date, not this is the only legitimate form of this book.

And it cannot be checked by a reader who does not know how to compute it. That is a real barrier, and pretending otherwise is how honest technical writing turns into a smug little club. Which is why the next section exists.

How a normal person checks it

On Windows, open PowerShell in the folder that holds the file and run Get-FileHash .\book.epub -Algorithm SHA256. On a Mac or Linux machine, shasum -a 256 book.epub. Both print a long string. Compare it, character by character, to the number published with the listing.

It is not fun. It takes ten seconds. You will almost always find that the numbers match, and that is the point: a small, boring ceremony that makes a quiet guarantee real. The alternative is trusting a file because it has the right name, which is how people end up quoting a book that no longer exists.

The wider habit

I have started doing this for audio and for images too, because the same problem appears everywhere. A WAV gets re-encoded by every platform and the "same" track is suddenly three different waveforms. A cover image gets resized until the type is mush. A hash does not stop any of that. It just ends the argument about what changed, which is the only argument worth having.

If you write, publish one number per book. If you publish music, publish one per master. Put it somewhere that does not move: a page on your own domain, next to the download, with the date. Then never change it quietly. The number is the cheapest form of integrity available to a person with no legal department, and it costs nothing but attention.

The practical version for this house is in The Unwritten Seal, where the ISBN and the file live together. The philosophy is Empty beats fake: name what you actually have.
